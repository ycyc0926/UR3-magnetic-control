# 相机程序

## H 机器人实时定位（2026-09-19）

启动：

```bash
bash /home/yc/UR3/camera/start_h_tracking.sh
```

浏览器打开 `http://127.0.0.1:8767/`。启动前关闭占用相机的旧预览窗口。
页面显示目标轮廓、中心、桌面世界 XY 坐标、相对位移和静止时的坐标波动。
初始在画面中心附近寻找黑色目标；点击图中的 H 可重新选择。跟丢后暂停发布位置，
从下一帧扩大到全画面搜索。只有唯一候选连续 3 帧通过检查才恢复坐标输出；多个候选时继续等待。
确认期间相邻中心须在 35 像素以内；候选消失、跳变或图像超时会重新计数。
确认帧数可通过 `flir_vision.yaml` 中的 `reacquire_frames` 调整，最少为 2。

当前方法是选定黑色轮廓的跟踪，不是通用 H 分类器；没有测量机器人的朝向。
重捕获沿用面积、形状和边界约束；仅凭唯一黑色轮廓和连续位置不能保证目标身份。
`/h_robot/pose_world` 单位为米，frame 为 `table_world`，orientation 只是占位值；
Z 为亚克力运动平面高度。翻滚时物体离开平面、轮廓变化会引入定位误差。
程序先恢复全传感器视野，再将半尺寸画面坐标还原到全分辨率，去畸变后映射到板面。
相机位置、镜头、板面变化后须重新验证映射；当前实物距离比例仍待核验。

只发布 `/h_robot/pose_world`、`pose_pixels`、`detected`、`tracking_score` 和
`image_annotated`。跟踪分数是启发式分数，不是概率。此启动方式不包含机械臂、
电机控制或自动停止接口，不能直接当作安全闭环使用。位置消费者必须同时检查
图像时间戳和目标有效标志。

仅预览或执行主程序任务时，图像、坐标和诊断只在内存中更新，不创建相机会话目录。
点击“开始连续录像”时，若主程序正在执行并记录实验，保存到该实验的
`experiments/实验时间/h_robot/clip_录像时间/`（也跟随主程序的 `--output`）。
没有正在记录的实验时，保存到 `experiments/camera_only/录像时间/h_robot/clip_录像时间/`。
保存位置在点击开始时确定，本段录像中途不会切换目录；主程序退出后不沿用上次实验目录。
只保存 `clip_*` 内的视频、逐帧 CSV、元数据和轨迹图，外层不保存日志、截图或状态文件。
结束或超时后停止写入，下一次录像创建新的 `clip_*`。
当前浏览器预览避开了本机 OpenCV/GTK 空窗口的启动阻塞。关闭浏览器不会停止
相机采集；在运行脚本的终端按 Ctrl+C 可停止相机和定位进程。

实验数据索引见 [`tracking_sessions/README.md`](tracking_sessions/README.md)。四段已确认
H 明显移动的录像另有不复制数据的快捷链接，位于
[`motion_examples/`](motion_examples/README.md)。

### 连续录像与失锁诊断

页面保留目标选择、清空轨迹、开始录像和结束录像四个按钮：

- “开始连续录像”：默认最多 120 秒，记录接收到的未画框图像，即使目标丢失也继续记录。
  每段先在 `clip_时间/` 中写入 MJPG `unannotated.avi`、逐帧 `frame_times.csv` 和元数据。
  视频为半分辨率 1224×1024、有损 MJPG，不是传感器 RAW。分析时间用逐帧时间戳，
  不只依赖视频的标称 20 fps。程序未收到的相机帧无法补录；元数据报告接收帧最大时间间隔。
- 录像结束时用五帧中值后的世界 XY 中心判断是否运动。中心活动范围达到默认
  `0.5 mm` 阈值时保留视频，并自动生成 `trajectory.png`；网页也显示最近保留录像的轨迹。
  未达阈值且跟踪完整的静止段会删除整个 `clip_*` 目录，不保留在本地。
- 筛选只判断中心位移，不判断转向。若有长时间丢失、录像期间人工重选或自动重捕获，或有效位置少于
  80%，程序不会冒险误删，而是保留视频并标记为“无法判定”。
- `frame_times.csv` 现在同步记录每帧的世界 XY 中心；轨迹图不连接跟踪缺口，不用预测点填补。
- 每段最长 180 秒、单段约 512 MiB 上限，预留 2 GiB 磁盘空间。新筛选不追溯删除旧记录。
- 检测诊断和重捕获确认帧数在页面实时显示，不另存日志文件；`frame_times.csv` 保留逐帧检测状态。
  不使用预测位置冒充测量，重捕获前后的轨迹分段记录。

**结束录像、录像超时、关闭网页、检测丢失都不会停止电机。** 电机仍由现场人员控制。
本程序无电机/机械臂控制接口，不能作为自动运行的安全联锁。

使用显式事件监听，不依赖 DOM 隐式全局变量；“已提交”仅表示请求进入后台队列，
后台拒绝原因单独显示，网络错误不被状态轮询清除。开始录像后须确认帧数增长。
完整可见的目标可在靠近画面边缘处跟踪，不再排除四周 7% 的区域。
边缘过滤仅拒绝触碰真实图像边界、可能被截断的轮廓；面积、形状和位移门限仍然有效。
初始目标靠边时请点击 H 选择；跟丢后自动重捕获，仍可随时点击 H 手动重选。

真实 Firefox 回归测试另见 `test/test_h_preview_browser.py`：只连接独立测试浏览器，
测试服务为临时 loopback 端口，无相机、机械臂或电机接口；覆盖四个按钮、选点、错误提示。

## 实时画面

运行：

```bash
./start_flir_camera.sh
```

桌面的“FLIR相机（全分辨率）”快捷方式指向同一个脚本。
跟踪服务已运行时，直接打开 `http://127.0.0.1:8767/`，复用现有的 1224×1024 跟踪画面。
没有跟踪服务时，脚本检查 USB 相机、恢复 `2448×2048`、`BayerRG8` 和自由运行模式，
再启动全分辨率查看器。相机被其他程序占用或初始化失败时会显示错误。
需要全分辨率查看器时，先在跟踪终端按 Ctrl+C，再双击桌面图标。

当前设备：FLIR Blackfly S BFS-U3-50S5C，序列号 `22165884`。

新版 Spinnaker SDK 独立安装在 `/opt/spinnaker-4.2.0.88`，旧版 SpinView 环境仍保留在 `/opt/spinnaker`。
